# Wave Shooter

**Holdout** is a browser wave-survival shooter in the style of Modern Warfare 3's Survival mode. Hold a village square against waves of soldiers, attack dogs, juggernauts and helicopters. Earn cash for kills and survived waves, then spend it at three armories:

- **Weapons:** pistols, SMG, assault rifles, shotgun, sniper rifle, LMG and an RPG, plus red dot sights, foregrips and extended mags.
- **Equipment:** frag grenades, body armor, a self-revive kit and a sentry gun.
- **Air support:** a precision airstrike, a two-man Delta squad and an attack helicopter.

Play solo, or host a co-op room for up to four players with voice chat. Co-op runs peer to peer over WebRTC (PeerJS), so there's no server to run: friends open the page, type the 4-letter room code and join.

## Play

Open `index.html` in a browser, or host the repo on GitHub Pages (Settings → Pages → Deploy from a branch → `main` / root).

Controls: WASD to move, Shift to sprint, C to crouch, mouse to aim and shoot, R to reload, G for a grenade, V to knife, F to use an armory or hold to revive a squadmate, 4 to deploy an airstrike or sentry, N to start the next wave early, M for voice chat. Phones and tablets get on-screen controls.

## How it's built

Soldiers are an animated glTF model in `models/`, loaded with the three.js loaders in `lib/`; if it fails to load, the game falls back to its built-in soldiers. Third-party assets and their licences are listed in `CREDITS.md`. The game is in `index.html`: three.js r128 from cdnjs for rendering, synthesized sound, no build step. Surface textures (stone, plaster, roof tiles, cobbles, wood, metal, camo and so on) are JPEGs in `tex/`, generated by `tools/tex.py` (Python 3 with NumPy and Pillow): run `python3 tools/tex.py tex` to rebuild them all, or add names to rebuild some, like `python3 tools/tex.py tex cobble roof`. Each set is a colour map `_c`, a normal map `_n` and, for some, `_r` with ambient occlusion in red and roughness in green. `peerjs.min.js` is a local copy of PeerJS 1.5 for co-op (the page falls back to jsDelivr if it's missing).

For local co-op testing, run a PeerJS server and open `http://localhost:8000/?peerServer=localhost:9000`.

### Co-op relay

Players normally connect directly. Some networks, mobile data especially, block that, and joining fails with "Couldn't connect to that room". A relay (TURN) server fixes it. By default the game uses free public relays (PeerJS's and Metered's open relay), which need no account but can be busy. For a dependable one, sign up for the free plan at [metered.ca](https://www.metered.ca/), then put your app name and API key into `RELAY` near the top of the networking code in `index.html`. The key is meant to be used from browsers, and Metered caps usage on the free plan.

## Versions

Every release stays playable. `index.html` is the latest build, `versions.html` lists the older ones, and each old build is a frozen copy in `versions/`. Before changing `index.html` for a new release, copy it to `versions/<n>-<name>.html`, add a card for it in `versions.html`, and bump `NET_PREFIX` in the new build so old and new co-op rooms don't mix. From version 4 on, a frozen copy loads its textures from `tex/` one folder up, so change `'tex/'` to `'../tex/'` in `loadTex` in the copy, and keep any texture an old version uses. From version 5 on, do the same for `lib/` (the script tags) and `models/` (the soldier loader).
